# 评论标准 Unicode 表情字形

2026-11-01。复用既有正式评论 Sheet，不新增入口、布局、像素对齐或功能完成量。当前问题来自用户选择的全局字体覆盖评论正文时，iOS 未能稳定回退到系统彩色表情字体；真实酷我/咪咕截图中的标准 Unicode 表情曾显示缺字方框。

## 场景

- 合成场景：酷狗公开评论正常入口的首屏热门评论同时包含音乐、职业女性 ZWJ、红心、家庭 ZWJ 和旗帜表情；保持普通文字、正文选择、作者、时间/点赞、热门/最新分区和加载更多的原行为。
- 真实场景：继续使用各平台生产入口与匿名公开服务，只记录字形是否可读；真实昵称和正文只留本机忽略目录。
- 无障碍：评论正文的完整 label 保持原顺序和原文，分段仅改变字体属性，不丢失 emoji、变体选择符、ZWJ、肤色、旗帜或组合音标。

## 实现约束

- 普通文字继续继承用户选择的全局字体；仅 emoji 簇显式使用 `AppleColorEmoji`。
- QQ 的 `[em]e…[/em]` 标记仍按原有安全占位规范化，不伪造平台图片表情。
- 不新增网络请求、持久化、日志或第三方表情资产；不改变评论归属、分页、失败保留和播放副作用边界。

## 验收

- 纯函数覆盖单码点、VS16、ZWJ 家庭/职业、肤色、旗帜、keycap 与普通组合音标，所有分段拼接必须等于原文。
- 合成 Release UI 从正常搜索/歌曲菜单进入评论，断言含 emoji 的热门正文完整无障碍 label，导出并亲看同源截图；真实服务专项另跑，不以合成截图替代。
- 精确绑定本轮 xcresult、源码/原生/JS 摘要；云端终态、实体机、签名和动效分别记录。

## 本批结果

- `npm run check` 914/914；合成、真实酷狗和综合 CI 路径 Release UI 均 1/0/0。
- 合成与真实 manifest 的 `sourceUnchanged` 为 true；综合路径精确执行 `testZNavidromePlaybackAndCredentials`，三个结果来源与哈希见[实施回执](../2026-11-01_kugou-comment-emoji-report.md)。
- 本机模拟器对 system font 与显式 `AppleColorEmoji` 的原生诊断均缺字，属于当前字体运行时缺陷。可视字形、iOS 27 云端、实体机、签名和动效未通过。
