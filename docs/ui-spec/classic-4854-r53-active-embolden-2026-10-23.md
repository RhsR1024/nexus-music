## 解释与决定

- 墨量与宽度都对齐而 SSIM/ΔE 下降，只有一种解释：参考的 active 行不是“同形状横向膨胀”，而是**字形轮廓/笔画分布不同**（更可能是另一字重实例或不同渲染路径，如真实 Heavy/Black 字面，而非系统字体 + 三重描边）。继续调 embolden 只会在“总量对、形状错”的方向上越走越远。
- 依据 `docs/UI_ALIGNMENT_WORKFLOW.md`：同一层连续两次数值尝试（r48 字重、r53 膨胀）无改善，暂停该层调参，不做第三次描边试参。
- 决定：源码回退到 r49 最优状态（`activeEmbolden:.1`），r53 作为**负证据**保留 spec 与报告，不合并为产品变更。回退后歌词区维持 79.52% / 5.34，为当前 best-known。
- 边界：不得为追平 SSIM 而调整遮罩、阈值、参考图或夹具；r32 canonical scene 不变。

## 决定（追加）

- 产品保留 r49 状态（`activeEmbolden:.1`）；r53 的 `.26` 与本次探针均为负证据，不进入产品。
- 同层第三次试参不做。若未来继续，须先从 Sollin 二进制/字体资源取得 active 行真实字号、字距或字重常量，再用单变量验证；在此之前不猜参数。
- 逐行 `cy` 差异（line1/line3 上移 1px）属于行盒/基线层，未与字重混在同一批；后续如有独立证据再单变量处理。
