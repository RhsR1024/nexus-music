# 下载任务选择边界回归

本批只修正正式下载任务页已有选择行为，不新增 Sollin 功能或采集。沿用 E-1300/F-098 的任务管理入口与任务记录/已保存文件分离边界；“取消全选”的清空行为依据音枢当前按钮文案和共享选择模型，不能称为新增参考 App 动态证据。

固定场景：正式设置 → 下载管理 → 下载任务与文件；合成 Navidrome 长队列中两首 120 秒 WAV，显式设置 2 并发并保持两任务在途。正常长按任务内容进入 1/2，点击另一条到 2/2；点击“取消全选”留在选择模式且变为 0/2，五项提交禁用；再次全选到 2/2，继续批量暂停、取消、重试至两文件保存。已保存文件长按不得进入任务选择，删除仍走独立确认。

本批不改容器、字体、图标尺寸、间距、颜色或材质，几何仍为正式组件的既有布局，无新的 px→pt 还原声明。候选全屏截图核对选择栏计数/按钮文案、空选择禁用状态与完成文件的正常删除入口；不以合成内容截图宣称参考页面像素或动效一致。Release 构建、精确 xcresult、fixture/源码/图片哈希及亲看结果在阶段回执补录。

原缺陷：选择栏显示“取消全选”却总是调用 `selectionAll`；完成文件复用任务行的长按/选择标记但动作载荷排除完成文件，造成可见选择和操作范围不一致。修正预期：清空选择并保留模式；完成文件不呈现任务选择状态。

同源缺陷扩展核验：搜索歌曲组和发现详情也只调用 `selectionAll`。三个调用方复用新增的 `selectionToggleAll`，按当前页 ID 判断是否全选，保留本地列表原有正确行为和收藏/队列动作的顺序。搜索固定一条合成结果验证 1/1→0/1→1/1；发现正常两首详情验证 1/2→2/2→0/2→2/2。空选择四项提交禁用，取消模式恢复普通行。增加两态全屏截图与对应正式入口回归；无新几何或参考一致性声明。

最终测试为同源码独立 Release：下载任务 `SourceUITests-1793612699584` 1/0/0、257.578 秒；搜索/发现 `SourceUITests-1793613088076` 2/0/0，聚合用例时间 257.072 秒。两个 manifest 的 `sourceUnchanged=true` 且源码 digest 同为 `530a1e85…`。下载任务 5 PNG 与搜索/发现 2 PNG 均为 1290×2796、逐张 provenance ready 并亲看；选择清空后动作禁用、完成下载行不再可被任务选择，页面安全区与正常导航保持。截图和 run manifest 的精确哈希见[阶段回执](../2026-11-02-selection-boundary-report.md)。
