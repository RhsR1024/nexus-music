# `withBase` 注音跨行场景

2026-11-05。J37/F27 的音枢自有 TextKit 布局修复；使用正式全部歌词页面及合成 TTML，不新增 Sollin 逆向结论。

## 状态与验收目标

基础文本为“一二三四五六七八九十甲乙丙丁戊己庚辛壬癸”，上方注音为 `abcdefghijklmnopqrst`，声明 `rubyAlign="withBase"`，20 个组合字素逐项配对。基础文本允许自然跨行，每个注音必须跟随对应基础字素；不得把整段注音挤在首行。数量不等的 `withBase` 继续回退中心对齐和原有基础组保护。首轮 16 字夹具在常态阅读宽度内仍为单行，已保留失败并扩成长样本，不降低跨行验收要求。

从正式播放页进入全部歌词并滚动到该段，检查整行可达以及注音分行对应。正常字号要求整段完整进入阅读视口。XXXL 若该 20 字段高超过视口，则验正常纵向滚动：首端进入顶部四分之一区域、末端进入底部四分之一区域，分别截图；段高须不超过 1.5 个视口，两张各覆盖至少 0.75 个视口的截图有连续覆盖，不能跳过中间文字。未超高时仍要求完整进入单帧。该规则在第二轮 XXXL 前确定，用于长内容阅读验收，不把正常滚动裁剪误判为注音缺失。

正常字号和辅助字号 XXXL 各自独立运行，保留原有 AMLL、rtc、rbc、双侧注音及 start/center/end 样本完整可见断言。截图检查基础与注音的行归属、阅读区裁切和控件可达性；不使用遮罩，也不设像素相似度分数。

两种场景的预期截图为 1290×2796 像素（430×932pt、3x），实际尺寸和精确构建来源以导出索引及运行清单为准。XXXL 是布局压力回归，不扩大当前 iPhone 常态 UI 美术验收范围。

## 实现边界

仅组合字素数相等的 `withBase` 放开基础组内换行；按 TextKit 实际行字符范围分段，拒绝重叠、缺失及拆开组合字素的行映射。各行独立计算注音起点并使用统一字号。普通注音保持 WORD JOINER 防拆，不改变权威播放队列或歌词时间线。
