# 黄金态 UI 规格与视觉实验室

这套规格回答一个问题：**同一状态下，候选页面与 Sollin 截图的差距在哪一轴、哪个区域，是否达到门禁。**

它不把整屏 SSIM 当作完成度。封面、歌词文本、背景渐变来自不同内容时，整屏分数有数学上限；门禁只落在可从工程侧修复的控件区。

## 四轴

| 轴 | 度量 | 用途 |
|---|---|---|
| 几何 | 7×7 局部 SSIM 均值 | 布局、间距、尺寸、锚点是否一致 |
| 颜色 | CIE Lab D65 的 CIEDE2000（均值 / p50 / p90 / p99） | 主题底色、卡片、强调色、遮罩色 |
| 墨迹 | Sobel 梯度相关性 + 密度比 | 字形/图标边缘是否落在同一位置；不是字体识别 |
| 内容 | 内容遮罩内的 SSIM 与面积占比 | 明确哪些差异来自封面/歌词/文案，并给出“内容完全一致”的理论上限 |

动效与手势不在静态实验室里。它们仍需真机录屏，不能用截图替代。

## 状态冻结

每个 JSON 固定：

- `reference` / `candidate` 的路径与 SHA256；
- `state`：主题、背景类型、卡片透明度、滚动落点、播放态等；
- `contentMasks`：不可复原的内容区（封面、歌词文本、不同曲目文案）；
- `controlMasks`：控件区门禁实际评估的区域（通常再排除文本内容带）；
- `colorPatches`：从参考图自动取均值的纯色块，比较候选同位置的颜色；
- `targets`：控件区 SSIM ≥ 90%、平均 ΔE00 ≤ 4、墨迹相关 ≥ 0.35。

参考图是 Display P3 16 位；实验室先用 macOS `sips` 做 ICC → sRGB 8 位转换，再计算。候选若已是 sRGB 也统一走同一条管线。

**候选截图必须来自同一测试方法、同一附件名、同一设备尺寸和主题。** 换状态、换 sheet 展开度、换滚动位置的截图不能互相比较。

## 运行

```bash
npm run visual:lab -- --spec docs/ui-spec/4854-classic.json
npm run visual:lab
npm run visual:lab -- --baseline docs/ui-spec/baseline-2026-10-21.json
```

输出在 `build/visual-lab/<id>/`：`report.json`、`diff-deltae.png`、`side-by-side.png`。报告包含 6×8 网格的 SSIM、ΔE、墨迹相关，用来定位最弱区域。

`scripts/visual-diff.mjs` 只保留历史灰度 SSIM 对照；它的 16 位路径仍是高字节截断，**不再作为颜色或验收证据**。

## 复现性

实验室分两层验证，避免把“截图不稳定”误判成“UI 没对齐”：

1. **指标复现**：同一组冻结输入重跑 `visual-lab --all`，所有 SSIM、ΔE、墨迹、色块、内容占比与基线清单逐字段一致。
2. **截图复现**：`scripts/visual-repro.mjs` 比较同一状态的两次独立运行截图。可比区（`ignore-top 180`）当前为 **0 个不同像素、SSIM 100.00%、ΔE00 0**。

```bash
npm run visual:repro -- --a <截图A> --b <截图B> --out docs/ui-spec/repro-<state>-<date>.json
```

证据：`repro-vinyl-2026-10-21.json`、`repro-classic-2026-10-21.json`。两份截图来自不同批次/独立运行，文件 SHA256 不同（状态栏时钟），但应用内容逐像素一致。因此后续页面分数变化只能来自代码或状态变化，不来自截图噪声。
