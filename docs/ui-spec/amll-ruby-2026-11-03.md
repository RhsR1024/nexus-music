# AMLL/TTML 注音：界面场景与量测

## 范围与来源

本场景是音枢自有 TTML 能力，不来自 Sollin 最新截图、录屏或 IPA/APK 结论。正式夹具使用 430×932pt iPhone 常态窗口、默认 `blush` + `rose`，截图为 1290×2796 @3x。测试内容为合成 AMLL TTML：

```text
漢字（注音 kanji） ruby tail
```

## 可见布局

- 含注音的行按当前字号计算上方 inset：`ceil(clamp(points × 0.46, 9, 12) × 1.25 + 1)`pt。24pt 主歌词约预留 15pt。
- 注音字号为 `clamp(points × 0.46, 9, 12)`，24pt 主歌词约 11pt；若注音宽于对应基础字形范围，降至最小 7pt 以留出边界。
- 注音水平居中在基础字形范围上，左右夹紧视图边界；垂直方向位于基础文字上方并将顶部夹到 inset 内。
- 主歌词颜色继续跟随当前播放器皮肤；注音使用同一前景色 90% alpha，不使用额外主题或独立材质。
- 无注音行不增加 padding，不改变现有行高、滚动锚点、模糊或逐字高亮。

## 状态

| 状态 | 行为 | 验收 |
| --- | --- | --- |
| 当前行 | 保留逐字时间和注音，基础歌词与注音使用活动色 | 逐字动画继续，注音保持可见 |
| 非当前行 | 保留注音元数据，但单词时间停在 `86400000`，禁用旧行动画 | 注音持续可见，不再消费活动高亮 |
| 暂停 | 当前行位置冻结，注音相对基础文字不漂移 | 同一时间点截图稳定 |
| 多行/裁剪 | 只在支持的原生歌词布局中预留顶部 inset | 不得把注音绘制到相邻行 |
| 无注音 | 使用原 `NativeLyricLine` 路径 | 不增加空白或占位 |
| 可访问标签 | `可见基础歌词，注音：annotation...` | 标签包含基础文字和唯一注音，双击定位提示保持 |

## 无障碍

可见歌词文本不插入注音，避免把读音当作演唱内容；每个可点击歌词行的既有 `accessibilityLabel` 使用附加注释。相同注音去重后按出现顺序追加。该设计让 VoiceOver 有机会读出基础文字和读音，也保持行级定位、长按设置、背景歌词和舞台歌词原有交互。

标签存在测试不能证明真实 VoiceOver 发音、略读或语言切换行为；这些仍需实体设备人工验收。

## 限制

- AMLL 仅接受一个 `base` 与一个 `textContainer/text`，未覆盖多注音组。
- 标准 TTML `<ruby>` 仅验证解析并复用同一单词注音字段；不实现 `rtc`、复杂并列、换行注音或 TTML2 样式级联。
- 当前绘制始终放在基础文字上方；不支持右侧注音、跨多行分配、行间注音或多基础字形分组。
- 真实歌词库、任意字体字形、极端长注音、动态字号、小屏、横屏和实体设备仍未验收。
