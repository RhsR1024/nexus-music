# TTML `rtc` 注音：界面场景与量测

## 范围与来源

本场景来自 W3C TTML2 标准结构，不是 Sollin 截图、录屏或 IPA/APK 结论。正式夹具使用 430×932pt iPhone 常态窗口、默认 `blush` + `rose`，截图为 1290×2796 @3x。

合成歌词末行同时包含：

```text
AMLL：漢字（注音 kanji）
标准 rtc：音（注音 yin）
普通文字： ruby tail
```

## 预期布局

- 两个注音复用既有 `NativeLyricLine` 顶部 inset，不因结构来源不同增加第二套行高。
- `kanji` 横向居中在“漢字”基础字形范围，`yin` 横向居中在“音”基础字形范围。
- 两个注音和基础文字共用当前歌词前景色，不引入额外主题、材质或独立状态。
- “ruby tail”不带注音，保持普通基础歌词的逐字时间与绘制。
- 可访问标签继续由 `lyricSpokenText()` 生成，按单词顺序去重后为 `注音：kanji，yin`。

## 状态

| 状态 | 行为 | 验收 |
| --- | --- | --- |
| AMLL + 标准 `rtc` 同排 | 两个基础分别保留自己的单注音 | 截图可见两个上方注解且后接普通文字 |
| 当前/非当前行 | 沿用既有单词时间停车与活动色规则 | 不新增跨来源动画分支 |
| 单一 `rtc` | 一个基础载体 + 一个 `rt` | 解析与 App 纵向路径通过 |
| 歧义 `rtc` | 多注解、混用、缺基础或分组后游离文字 | 安全拒绝并回退，不猜测注音映射 |
| 无注音行 | 原轻量行路径 | 不增加占位或 spacing |

## 限制

当前只覆盖单基础、单注音槽和基础字上方的水平排列。双侧注音、`rbc` 多基础映射、多个注音内容、跨行分配、复杂字体、动态字号、小屏、实体 VoiceOver 和真实歌词库仍开放。
