# 动态字号注音与全部歌词阅读器

本批是音枢已有歌词能力的可用性修复，不增加 Sollin 观察结论，也不宣称大字号美术或完整 TTML2 排版完成。复用已固定的离线歌词证据；正式采纳仍执行 IPA strict review。

## 固定场景与验收

使用 `testAMLLProfileLyricsAtAccessibilityXXXL`，iPhone 15 Pro Max 模拟器、系统 Accessibility XXXL、正式 Release 组件和既有合成 AMLL/标准 TTML 混合歌词。从设置、合成音源、搜索、播放器进入全部歌词，不另造截图页面。主题使用测试持久化状态，本批不提供默认主题颜色相似度评分。

- 顶部设置区可独立滚动，最多占可用高度的 46%；歌词列表保留实际可滚动视口。
- 正常字号顶部区只使用内容高度，不能因 ScrollView 默认 grow 吞掉中间空间；固定测试态高度小于整屏 45%。
- 放大后的歌词及注音可达、可点击；目标行高度至少 100pt。
- 目标整行不高于歌词列表视口，截图时其上下边界均位于视口内；部分可点击不足以验收。
- 经典播放器的全部歌词入口须完整位于 `classic-player-scroll` 视口后再点击；入口跨越屏幕下缘时不能把 `isHittable` 当成默认点击点可用。
- 换行后的 `shuang` 位于第二行“双”上方，`sou` 位于其下方；`kanji/yin/duo/ji` 仍对应第一行基础文字。
- 两行注音不相交、不被首行坐标限制拉回，也不被列表裁切。
- 常规 `testAMLLProfileLyrics` 回归正常字号、定位与既有播放验证。

截图按模拟器附件实际尺寸记录，不将测试通过替代亲看；每次使用精确 xcresult 和独立导出目录。无参考录屏，不报告动效一致；实体 VoiceOver、真实歌词库、复杂单词跨行、多注解、签名安装及 iOS27 终态分别待验。

## 原因与实现

旧原生上方注音把所有 y 坐标限制在 `rubyInset-height`，后续行因此回到第一行。修正为相对本行基础字形顶部定位。系统辅助字号扩大注音上限，并在基础行之间保留上下两侧注音所需间距；React 测量与原生段落保持同一行距输入。全部歌词顶部控件独立滚动，避免挤掉歌词列表。

原先两次自动通过但截图仍重叠的结果 `SourceUITests-1793674469700`、`SourceUITests-1793674949643` 保留为未采纳证据。正常字号 `SourceUITests-1793676162886` 的顶部空白回归也保留，不能因自动通过而采纳。最终截图、哈希、构建 provenance 与验证结论见[本批专项回执](../2026-11-03-dynamic-type-ruby-full-lyrics-report.md)。
