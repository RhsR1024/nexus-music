# 播放链路诊断：交互与布局场景

2026-11-01，J57 部分纵向增量。沿用当前播放器更多菜单、Sheet 容器、blush/rose 默认主题和现有排版令牌；本页是音枢已有排障能力的结构化呈现，不新增参考像素门槛，也没有新增 Sollin 截图采集。

## 入口与容器

正式播放页打开“更多播放控制”，菜单中新增“播放链路诊断”，副标题为“匹配、选源、降档、解码”。点击后在同一详情容器显示“返回播放选项”和诊断正文，返回后恢复原菜单；不新建独立播放器或第二套队列。

| 状态 | 同内容条件 | 行为与布局 | 验收 |
| --- | --- | --- | --- |
| 空态 | 已恢复暂停队列但尚未解析媒体 | 标题、说明和“还没有播放解析记录”出现；不显示虚假运行 | 空态不伪造离线、选源或 native stage |
| 采集中 | 当前在线歌曲正在解析 | 当前 run 标记“采集中”；事件按时间递增追加，显示相对秒数、阶段、状态、来源、平台、档位和已脱敏详情 | 重新解析入口可达；旧 generation 不能污染新 run |
| 离线命中 | 永久下载记录可读 | 第一阶段明确“离线 · 命中永久离线文件”，详情说明本轮不会请求在线音源 | 在线匹配/源请求不出现 |
| 离线未命中 | 在线或导入歌曲没有永久文件 | “离线 · 永久离线文件未命中”后继续匹配/选源 | 不把未命中写成失败 |
| 匹配/选源 | 自动或人工目标取得媒体 | 手动/自动策略分开；候选、匹配成功、逐源失败/超时、最终档位和地址确定按序显示 | 不显示 URL、请求头、token、脚本输出 |
| 降档 | 偏好档位全部候选失败后取得更低档位 | 事件状态为“降级”，文案同时显示偏好和实际档位 | 不以 UI 文案代替真实文件格式证明 |
| 缓存身份 | 路由结果带 cacheKey | “已绑定原生媒体缓存身份”，区分仅缓存播放和可检查命中 | 缓存 id 不展示完整内部敏感字段 |
| 原生就绪 | AVPlayer 发出 ready | “原生媒体已就绪”，明确网络媒体或缓存文件解码成功；有有效时长时展示秒数 | XCTest 精确识别事件；ready 不等于全曲已播放 |
| 路由失败/重试 | 原生路线失败且 controller 仍可换路线 | 失败 run 保留为“失败”，新 generation 以“采集中”出现 | 旧失败不因后续成功被抹除 |
| 取消 | 新播放、暂停、队列切换、媒体失效或释放 | 运行记录收敛为“已取消”，不再追加迟到事件 | 新 generation 与旧事件隔离 |

## 视觉与可达性

- 页面顺序为返回按钮、24pt 标题、说明、重新解析按钮、最多六张运行卡和“ready 边界”说明；运行卡首行为歌曲/歌手/代次与状态徽章，事件使用 48pt 时间列和弹性正文。
- 重新解析按钮最小高度 46pt；所有事件保留文字状态，不依赖红/绿颜色单独表达。标题使用系统标题语义，返回、重试和事件使用稳定 testID。
- 默认主题下的表面、细线、强调色和文字层级来自现有主题令牌；没有引入散落颜色常量或新图标体系。
