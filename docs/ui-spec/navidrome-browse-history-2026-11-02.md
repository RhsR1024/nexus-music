# Navidrome 浏览层级与上下文恢复

对应 F15 / S8 的音枢自有私人曲库。依据现有 `NavidromeLibrary`、账户仓储与 OpenSubsonic 客户端原创补强，不采纳新的 Sollin 结论、参考资源或第三方实现；不增加 provider/播放器/队列，不探测私人服务器。五参考维护/Android/许可边界继续见 `docs/REFERENCE_COMPARISON.md`，本批不移植其源码或原生依赖。

## 当前缺口与功能要求

旧组件只保存一个 view；点歌手、专辑或服务端歌单会清空 items/offset 并请求新列表，没有返回父层的入口。父层页码、已加载内容、搜索草稿和服务端歌单名称草稿无法恢复。

1. 歌手列表 → 歌手的专辑 → 专辑歌曲提供逐层返回。专辑、歌单详情均返回实际父层；标题来自该层真实服务端数据，不猜测名称。
2. 返回恢复父层 items、已加载 offset、是否可继续加载、50项可见页、标题、输入和错误。已成功载入的父层返回不重新请求。保存的是分页上下文，不承诺恢复外层 ScrollView 的精确像素滚动坐标。
3. 四个一级分类可恢复本次浏览会话的已载入页和搜索文本；提交的 query 与尚未提交的输入草稿分开保存，继续分页使用已提交 query。
4. 刷新和分页失败保留已载入内容；分页重试使用失败的同一偏移，成功刷新回第一页。返回或换分类取消当前请求；换/移除/重新连接账户清空所有浏览历史和分类缓存，迟到结果不能覆盖新连接。
5. 服务器写入继续使用原账户客户端。导航不持有密码、token、认证 URL、音频数据或客户端实例，不进入持久存储或备份；曲目仅采用现有白名单元数据。队列与播放意图继续由原控制器维护。
6. 取消的 client 获取不得再发起网络请求；卸载组件取消请求。重命名服务端歌单时更新已保存的列表标题，服务端星标成功后同步本次会话各层缓存中的同曲状态并保留当前页；失败不预先改变星标。其他服务端写入仍按原刷新路径执行。

## UI 与正常操作

当前为 iPhone 常态范围，使用现有私人曲库排版、按钮、主题和分页渲染。在详情标题前新增明确“返回〈父层标题〉”入口；长标题允许换行，不能遮住账户、分类、播放和服务器操作。保持每页50项有界渲染，不为截图隐藏操作或另做测试页面。

本批没有 Sollin 对应页面/状态，不进行像素相似度或参考动效等价声明。质量验收以实际页面亲看、控件可达、父子层级明确和内容不丢为准；截图仅证明所采状态。未采集系统返回手势或转场录屏，不声明手势/动效一致。

## 验证场景

- 合成 OpenSubsonic 服务：120位歌手、某歌手65张专辑、专辑120首歌、120个服务端歌单；均使用合成身份，无真实用户资料。
- 歌手第二页 → 专辑第二页 → 歌曲第二页实际点击播放到原生频谱 → 暂停/收起 → 返回两层仍分别为原页；继续载入歌手第三页，再进详情返回仍保留120项。
- 已提交歌曲搜索与第二页 → 服务端歌单第二页 → 详情/返回 → 切回歌曲仍保留输入与结果页。
- 切换第二个合成账户后没有旧返回栈、旧搜索或旧已加载项；测试结束只移除两个唯一夹具账户。
