# TTML `rbc` 多基础注音：界面场景与量测

## 范围与来源

场景来自 W3C [TTML2 10.2.35 `tts:ruby`](https://www.w3.org/TR/ttml2/#style-attribute-ruby)，不是 Sollin 截图、录屏或 IPA/APK 结论。正式夹具使用 430×932pt iPhone 常态窗口、默认 `blush` + `rose`，截图 1290×2796 @3x。

合成歌词末行包含：

```text
AMLL：漢字（注音 kanji）
标准 rtc：音（注音 yin）
标准 rbc：多基（按顺序注音 duo、ji）
普通文字：ruby tail
```

## 预期布局

- 四个注音复用现有 `NativeLyricLine` 顶部 inset，不为 `rbc` 增加第二行高或独立容器。
- `duo` 以 `多` 的字形范围居中，`ji` 以 `基` 的字形范围居中。
- 基础词、注音与普通尾文字共用当前歌词前景色、活动色与透明度。
- “ruby tail”保持普通单词时间，不继承任一注音。
- 可访问标签按基础词顺序去重为 `注音：kanji，yin，duo，ji`。

## 状态

| 状态 | 行为 | 验收 |
| --- | --- | --- |
| AMLL + rtc + rbc 同排 | 四种注音按各自基础范围绘制 | 正式截图亲看可见 |
| `rbc` 基础少于注解 | 无定义映射，安全拒绝并回退 | 契约拒绝 |
| `rbc` 基础多于注解 | 无定义映射，安全拒绝并回退 | 契约拒绝 |
| 基础有显式时间 | 词时间由基础元素决定 | 契约精确毫秒断言 |
| 基础无显式时间 | 使用对应注解时间 | 契约精确毫秒断言 |
| 第二 `rtc` / 双侧注解 | 当前单注音槽不支持 | 拒绝，不猜测方向 |
| 无注音行 | 原普通歌词路径 | 不增加占位 |
