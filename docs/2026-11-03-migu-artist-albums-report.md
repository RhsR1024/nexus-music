# 咪咕艺术家专辑与数字专辑

咪咕艺术家专辑页改用官网当前ID目录，并接入普通专辑、数字专辑的不同公开详情。数字专辑明确标注只读到公开曲目，导入按钮、确认框与新建歌单说明均保留这个范围；不把公开返回7首写成完整发行版15首。原F/J目标、全部平台状态矩阵及实体机/签名验收继续开放。

## 来源与实现

Evidence：官网`music.migu.cn/v5`的`singerDetail-2b271d81.js`、`index-c7c96a78.js`和`@migusdk-617e3513.js`发布艺术家专辑、普通专辑资料/曲目、数字专辑资源的独立调用；实际匿名HTTPS响应交叉核验。后两模块SHA-256为`621081e118227a3918fc505bf41d543ef8e11ef849ace129c31f672f3157732b`和`41fa13084cffa15fc23f022b6a8f27bf73def9e22214ef62b6605a06dacb7269`。只采用公开协议事实，自写适配器，不复制官网实现、素材、依赖、登录或购买逻辑。五参考既有实现/维护/Android/许可比较沿[参考比较](REFERENCE_COMPARISON.md)，无新增第三方实现采纳或Sollin结论。

Finding：艺术家专辑固定10条/页；普通专辑是`resourceType=2003`，数字专辑是`5`且歌曲指向数字资源自己的`dalbumId`。专辑搜索同样明确返回这两个类型，旧适配器丢失了该字段。官网数字专辑资料可返回空`songItems`，资源详情才返回公开曲目；不能把第一个空列表当空专辑，也不能从简介文字制造缺少的曲目。

Path：`miguAlbums.ts`提供有界重分页及完整公开快照，校验艺术家续页、专辑ID/类型、逐曲专辑归属、总数、分页推进及取消。仅请求固定官方HTTPS地址，不跟随响应的旧HTTP续页URL。普通专辑先核对资料，再收齐曲目并校验计数，保留顺序和重复项；数字资源核对唯一资源与完整公开曲目数，并保留歌曲/版权ID、时长、音质、歌词和安全封面。

数字目录使用内部`migu-digital-`前缀，与普通专辑分开；搜索、艺术家页、目录收藏和同步序列化保留身份，界面不显示前缀。旧收藏/备份中的裸ID先查普通资料，仅在官方成功信封明确缺少资料时查数字资源，并要求完整ID/类型/逐曲归属匹配；网络失败、错误类型或外来身份不触发猜测回退。无需改写已有用户收藏。

详情的`scope=public`随完整读取保留到导入确认。用户明确创建歌单时附“来自平台公开目录，仅包含本次可读取的曲目”说明；本轮App只验证预览取消，未向用户库新增歌单。TS逻辑可用于未来Android，未增加Android交付或原生补丁；LX、Navidrome、播放器仍保持独立边界与唯一队列。
