# LX 歌单解析 P4/P5 回执（2026-10-23）

P4 收紧 `lxTrack` 的五平台身份、元数据与预算；P5 用正式 App 入口走通 Files→LXMC→同一 parser→预览→取消→确认导入→重启→删除。业务测试与 App 测试均通过，但真实 LX 导出文件、真实平台服务、云端 iOS 27 终态和真机仍未验收，不能据此宣布“全部 parse 完成”。

## P4 实施

|位置|行为|边界|
|---|---|---|
|`src/storage/playlistJSON.ts` `lxTrack` 身份|仅接受 `wy/tx/kw/kg/mg`。kg 使用 LX 复合 `${songmid}_${hash}`：`id` 已含下划线时去平台前缀后原样使用；仅给 `2829` + `meta.hash` 时拼成 `2829_abcdef`；`kg_2829_abcdef` 与 `2829_abcdef` 归一为同一身份。tx 的 `tx_MID` 去前缀后得到 `MID`|不从缺失字段臆造 ID；无 hash 的 kg 保留现有 songmid，不伪造复合 ID|
|元数据|`metadata` 保留原 `meta`；`songId` 优先取 `meta.songId`，kg 复合 ID 无独立 songId 时不把复合串写入 songId|原始 `qualitys`、`songmid`、`hash`、`strMediaMid` 等不被改写|
|长整数|`parseProviderJSON` 在 JSON.parse 前给 ≥16 位裸整数加引号；`meta.id:9007199254740993123` 保存为字符串，不发生 IEEE754 舍入|该处理仅覆盖 JSON 数字字面量；科学计数/小数仍按 `parseProviderJSON` 既有规则|
|duration|`mm:ss` 且秒 <60；毫秒有限且 ≤24h（86,400,000）才写入 `durationMs`，否则省略|`1440:01`、超长数字串、`3:75` 均降级为未知时长，不截断为假值|
|qualities|`meta.qualitys` 去空/坏类型、长度 ≤128、按首次出现去重、最多 64 项|先限后去重不适用本字段的原始数组保留；原始 `meta.qualitys` 完整保留，展示用 `qualities` 才受限|
|预览与入库|预览与确认导入都消费 `decodePlaylistJSON` 的输出，不在导入端二次解释|32MiB/100 歌单/20000 曲上限不变；不支持的平台计数、结构错误整体失败不变|

## P5 实施与边界

正式入口仍是 `LibraryDataTools.tsx` 的“导入LX v2歌单 JSON / LXMC”：`DocumentPicker` 选中文件后，`.json` 走 `file.text()`，其余（含 gzip `.lxmc`）走原生 `decodeImportText`；预览 Alert 展示 collection/曲数，取消不调用 `library.importCollections`，确认后一次原子更新并经 `validateLibrary`/repository 持久化。`importCollections` 为每个 entry 生成新 ID，保留 collection 内顺序与重复曲目。

未改 UI 文案、播放路由或平台登录；P5 的验收对象是已有正式入口，不是新增旁路。
