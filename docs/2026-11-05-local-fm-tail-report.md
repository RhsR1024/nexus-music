# 本地 FM 尾批循环修复

修复本地 FM 在候选数量不是批次大小整数倍时反复跳过尾批的问题。

## 根因与实现

`LocalRecommendationStore.nextFM(count)` 原先只要返回数量小于请求 `count`，即使仍有未播候选也立即清空 `fmPlayed` 并从头取满一批。正式入口按 `nextFM(10)` 批量取曲，11首候选会形成 `10→10→10…`，第11首在该轮始终无法出现；3首候选按2首取同样会跳过最后一首。

现改为返回当前剩余候选的前 `count` 首；剩余为空且本轮确有播放记录时才重置并循环。不清空候选、不改排序/同歌手打散、播放入口、权威队列或持久化模型。刷新候选时移除失效身份的既有逻辑保留。

## 验证

- 修复前纯业务复现：11首、`nextFM(10)` 第二次返回前10首而非第11首，日志 `build/local-fm-tail-before-20261105.log` 保留失败。
- 新增 `tests/recommendations.test.ts` 用例：11首连续调用必须为10首、`tail-10`、10首；覆盖尾批不足批量的实际生产路径。
- `build/local-fm-tail-after-20261105.log` 为推荐专项4/4通过。
- `build/search-session-fm-check-20261105.log` 为最终源码1023/1023类型/业务检查通过。

本批为业务状态机修复，不新增平台推荐、账号、真实服务、UI或Sollin证据；完整平台 FM、真实长期循环和F30仍保持开放。
