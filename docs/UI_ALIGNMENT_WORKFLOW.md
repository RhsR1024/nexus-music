# Sollin UI 对齐实施与验收规范

生效：2026-10-21。依据：用户要求将本轮复核后的方法写入项目，供其他 AI 助手执行。决策见 [0078](decisions/0078-ui-alignment-workflow.md)。

本文件是当前 UI 对齐**方法与执行顺序**的唯一主规范，覆盖历史日志中冲突的“控件分过线即整页完成”“先全量 UI 精修再新增功能”“每次微调都完整归档”等做法。产品范围仍由 [PRODUCT_SCOPE](PRODUCT_SCOPE.md) 和 [0076](decisions/0076-iphone-normal-layout-scope.md) 定义；90% 是最低目标，不是停止优化的上限。

Phase 0 已有带哈希的五态基线、ICC 转换、局部 SSIM、CIEDE2000、边缘度量和部分截图复现证据；它是测量底座，不是整页或交互验收。基线和历史分数见 [ui-spec](ui-spec/README.md)。

## 一次页面迭代

| 顺序 | 执行动作 | 必须留下的证据 |
| --- | --- | --- |
| 1 同态 | 核对参考与候选的内容、主题、播放、弹层、滚动状态；不同态先修采集/夹具 | 场景清单、不一致项及处理方式 |
| 2 量测 | 对照原图先量容器、安全区、关键基线、控件边界，再列当前差异 | px→pt 量测、区域边界、容差、修改假设 |
| 3 实现 | 每次只改一个可归因的问题组，先容器后内部样式 | 修改组件、原因、预期受影响状态 |
| 4 快验 | 用正式组件直接进入固定场景，重新截图；查看并排、差异图、叠图/局部放大 | 新截图与哈希、指标、人工观察、回归结果 |
| 5 判断 | 改善则保留；退步先区分采集/内容/实现原因，不只按总分撤回 | 保留/撤回理由、剩余前三项差异 |
| 6 集成 | 样板或一组状态通过后，走正常入口和相关业务回归，再阶段归档/云端验证 | 实际入口、交互、构建版本及独立证据状态 |

连续两次尝试没有改善时，暂停同层数值试改，检查父容器、字体度量、数据状态和渲染机制；记录根因再继续。不得用扩大遮罩、降低门槛、改参考图或替换截图来制造进展。

## 固定场景，而不固定错误结果

每个场景记录以下字段；现有 JSON 未支持的字段可先写在同名说明或阶段回执中，不能声称脚本已自动校验：

- 参考截图路径、SHA256、原始像素尺寸、逻辑尺寸与比例；设备/OS/字体环境已知值与未知项。当前常用参考为 1290×2796、430×932pt、3x，不泛化到全部来源。
- 默认 `blush` + `rose`、明暗模式、背景类型、取色输入、卡片透明度、字号/字体、语言、区域和显示缩放。不能换 `classic/blue` 或任意调色主题来获得默认态通过。
- 曲目、封面、歌词/翻译、队列、播放/暂停、进度、选中项、弹层展开度、滚动锚点；动画取样时刻与稳定条件。
- fixture 版本/哈希、测试方法、附件名、精确 xcresult/运行 ID、候选源码提交与 dirty 状态；有未提交改动时保存可追溯补丁哈希。记录实际安装包/JS bundle 标识，不能把当前 HEAD 当成旧截图的构建版本。
- 内容不可比较区、音枢扩展区、必要的系统状态栏排除区及理由；量测坐标和区域覆盖率。

参考与状态规格冻结；候选随产品改动更新，每轮形成新证据。规格、遮罩、指标版本发生变化时建立新版本，对旧候选按新口径重算后才比较趋势；不覆盖旧基线。

### 内容与夹具

优先在有授权且可取得的条件下让两端使用同一封面、歌词、播放位置和主题。原版无法运行时，以现有截图中能确认的状态为基准；未知项如实记录，不能推测为已还原。

视觉场景夹具与功能压力夹具分开。视觉夹具匹配文字密度、行数、状态与已知素材；功能夹具保留长标题、坏图、长队列、网络错误等压力情况。改变视觉夹具时同时记录内容差异，不把分数变化归因于产品代码。

取色背景不同，先检查是否因为封面输入不同。不能为一张参考图硬编码全局背景，也不能把背景取色、歌词排版或封面裁切从整页验收中删除。没有同素材时，分别验算法/布局并将整页视觉证据记为不完整。

### 快速入口与正常入口

下一实施批次优先补独立场景采集：使用正式页面、正式组件、正式字体与渲染逻辑，只在测试构建中注入数据、时钟/随机输入和初始状态。禁止制作专用截图页面、截图背景或产品中不存在的假入口；正式分发包不得暴露测试入口/私有 fixture。

快速入口不走冗长的导入、连接和播放准备流程。等待图片/字体就绪、弹层稳定、滚动锚点成立后截图；固定时钟或动画采样只用于静态测试，不改变产品行为。至少两次独立采集确认本场景噪声，不能把其他场景的零差异结论外推。

快速入口通过后，必须从正式导航进入相同状态，检查打开/关闭、滚动、选择、保存恢复和受影响的播放行为。直接入口不能替代导航与交互验证。当前主要采集仍依赖综合 XCTest；快速场景、自动锚点检查、自动叠图、全量视觉 CI **不能仅因本文件存在就记为已实现**。

## 实现优先级

1. **容器与状态**：Sheet 高度/圆角/遮罩、头部与滚动内容归属、安全区、页面模式、播放意图。
2. **主体几何**：封面、标题/歌手/歌词、操作区的边界和布局约束，先父容器后子元素。
3. **字体与图标**：实际字体、字重、行高、基线、图标路径与笔画。视觉尺寸和至少 44pt 的交互命中区域分开处理；可访问性不能成为增加参考中没有的可见按钮的唯一理由。
4. **颜色与材质**：默认主题的色彩、透明度、背景取色、模糊、阴影；先统一色彩空间后比较。
5. **局部间距与动效**：稳定几何后微调；动效按独立行为规格验收。

若系统 `pageSheet` 无法表达参考的头部/滚动/拖动行为，先用有限原型验证容器方案，再局部定制；不在容器差异上叠加多处 padding/负边距。共享播放控制器和交互逻辑，各皮肤明确拥有布局规格；tokens 只集中真正共享的规则，不能强行把不同皮肤变成同一种排版。没有证据支持为这项工作重写整个应用框架。

音枢新增主题/能力单列为扩展区，保留入口和功能；记录如何兼容参考主结构。不能删除功能凑图，也不能将扩展区自动视为完成或从整个页面评价中隐去。

## 验收：指标辅助，关键缺陷不能平均掉

| 验收项 | 方法与初始约束 | 通过要求 |
| --- | --- | --- |
| 状态与来源 | 核对场景清单、构建、SHA、尺寸和主题 | 状态正确，来源可追溯；不满足则停止评分结论 |
| 结构/几何 | 容器边界、文字基线、图标中心、轨道端点的 pt 量测 | 关键锚点可从约 1–2pt 预算起步，结合参考与重复采集校准；无缺控件、错层级、遮挡、裁切 |
| 静态视觉 | 全屏记录＋语义区域 SSIM/像素差、色差、边缘及局部观察 | 所有关键区域均复核；大片背景的平均高分不能抵消错误图标/文字/容器 |
| 内容与材质 | 封面比例/裁切/圆角、歌词排版/高亮、背景取色分别验 | 排除照片纹理不等于排除封面布局；排除不同文案不等于排除排版 |
| 实际交互 | 正常入口的打开、关闭、滚动、选择、持久化、播放意图 | 不为像素对齐破坏既有功能，音枢扩展仍可用 |
| 动效/手势 | 原版与候选同起点/操作/终点录屏，比较关键帧、轨迹和时间 | 需真实设备录屏；缺参考只能记近似或待验，不能记一致 |

每态实施前冻结最终通过清单、关键ROI、几何容差、颜色/图标判据及人工否决项。若要报告“相似度90%/95%”，必须附预先确定的评分量表、权重、参照等级和逐项依据；没有可追溯量表时，只报具体指标和“静态验收项通过/未通过”，不另造主观百分比。关键缺陷不能用其他项加分抵消，改变量表须重评基线。

90% 是项目最低相似度目标，**不是上述指标的加权平均，也不等于 SSIM 0.90**。Phase 0 的 `SSIM ≥ 0.90、平均 ΔE00 ≤ 4、边缘相关 ≥ 0.35` 保留为已定义区域的初始自动门槛；还须校准语义区域、颜色尾部/关键色块、真实几何和人工结果。指标缺失/非有限值不得放行；分辨率、颜色管理或窗口算法改变须版本化。

SSIM 受亮度、对比度、内容影响，不能标成纯几何评分。边缘相关不是字体识别。没有参考录屏时，可以单记“静态态通过”，但整页 UI/交互任务仍未完成；不得用等待录屏无限阻塞已可独立推进的业务工作。

### 遮罩与度量校准

- 遮罩/包含区域在改产品前声明，记录面积、理由及被排除部分的补充验收；不得为过线临时缩小到少数按钮或暂停条。
- 度量前确认控制区和色彩采样区有足够且相关的覆盖；同时报告相对于完整应用画面的控件区覆盖、颜色区覆盖，以及ROI内部排除率；ROI内部100%不代表整页覆盖。覆盖率只用于揭示限制，不自动赋予“整页”资格。局部窗口与遮罩边缘的混入、重叠区域的面积统计应作为工具校准项处理。
- 先用已知差异校验门禁：移动关键控件、替换图标/字重、改错底色、缺失控件，应该在对应验收项失败；同态重复采集应反映真实噪声。不要在真实候选上调低阈值来校准。
- 局部 SSIM 算法与一份明确参数的可信实现交叉核验，保留参数/边界处理；现有色差测试通过不代表所有指标均已校准。
- `ceilingIfContentMatched` 仅是**固定当前非内容区域得分、假设内容完美时的条件估算**，还忽略局部窗口边界联动。不能称页面的理论极限，不能据此认定90%不可达。

## 证据保存与现有命令

原始截图、素材、视频、diff 和完整报告仍在本机忽略目录；仓库提交脱敏规格、来源/哈希、结果摘要和决策。不上传参考资产或私人内容。

正式证据使用精确 xcresult，禁止用 `latest` 自动挑图；固定附件名仍须核对实际画面、测试状态与哈希。每轮使用新目录，既有 `build/visual-lab/<id>/` 默认输出可被覆盖，不用于长期验收存档。

以下从项目根运行，使用已存在的 CLI；只示范对当前规格重算，不代表重新运行了 App 或通过页面验收。每次创建独立目录，因此不会覆盖旧实验：

```bash
source scripts/environment.sh
ui_audit_dir="$(mktemp -d "$PWD/build/ui-method-XXXXXX")"
node scripts/visual-lab.mjs --spec docs/ui-spec/4855-appearance.json --out "$ui_audit_dir/4855"
```

正式采纳前，确认该规格绑定本次正确候选，保存本次规格副本及其哈希、工具版本和构建来源。`--candidate` 覆盖不会自动校验规格里的候选哈希，`--skip-hash` 禁止用于正式验收。`--baseline` 是**写出**清单，不是“与旧基线比较”；不得指向已冻结文件。`npm run visual:lab` 已包含 `--all`，单态运行使用上面的直接 `node ... --spec`，避免误跑全部并覆盖默认目录。

当前 `visual-lab` 产出并排图与色差图；叠图、pt 锚点和逐区域最终验收仍需显式补充。每个接手助手必须读实际 CLI/代码确认能力，不能把计划功能写成已有工具。

## 进度与每轮交接

固定“页面×状态”清单和工作量权重，分别记录：代码结构已实现、静态态通过、正常交互通过、动效通过、真实服务/设备通过。没有证据的字段写待验，不能由其他列推断；样板5态不是全项目分母。

视觉完成量只取通过对应验收的状态权重；未过静态页不计已对齐量，动效未过的任务不计完整 UI/交互完成。已有骨架可以保留在代码实现估计中，但须独立说明，不能换名为已对齐。方法、门槛或文档更新本身不增加进度。

每轮在 [SOLLIN_UI_ALIGNMENT](SOLLIN_UI_ALIGNMENT.md) 留一条当前记录，交接只摘要和链接，不复制多份数字：

1. 本轮目标状态、原差异、修改假设与实际动作。
2. 源码/构建/fixture/截图/工具的版本与哈希、精确测试来源。
3. 结构锚点、全屏与各关键区结果、颜色/边缘、遮罩覆盖与补充验收、人工观察。
