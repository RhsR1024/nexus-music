实施要求：

1. CrossPlatformMatcher从仅imported扩展到普通online；跳过完全相同的来源ID，保留标题/歌手/版本/时长的严格自动标准。不确定候选只能人工确认。
2. 统一路由原曲与匹配目标。每档先试原曲全部源，再试可靠匹配；本档用尽才降档，不能先播放原平台128k而漏掉另一平台可用FLAC。候选搜索按需、最多两并发且有界，不每次播放先全平台搜索。
3. 手动版本优先并持久化，不在失败后偷偷换成另一录音。可取消绑定；自动匹配允许关闭。账号/本地文件/设备来源继续使用独立解析边界，不因普通在线匹配改造而发送到在线搜索。
4. 队列和曲库保存原始身份，TrackMatch扩展原曲online/imported、目标online；禁止自绑定；目标直接交给LX，不递归跟随其匹配记录，避免播放递归循环。缓存与解码重试键包含原曲/目标/源指纹/质量，所有原曲与匹配路由统一编码，避免旧排除项失效而反复播放同一坏地址。
5. 匹配修改后取消旧解析并使已加载媒体失效，等待用户再次播放；不能仅pause后resume旧URL。保留队列条目与合理定位游标，检查写入期间切歌的代次。
6. Player/曲库/列表提供人工版本与恢复自动入口，显示原曲、目标、置信度/版本信息和失败平台；去掉仅适用于汽水的硬编码文案。歌词使用匹配目标，原始收藏/歌单ID不替换。
7. 验证顺序：普通曲/汽水旧契约、同档全局质量优先、手动/关闭/取消、无可靠匹配、搜索部分失败、旧候选与源更新、解码排除键、写失败保留、备份往返；再合成App入口/手动版本/播放回归与真实服务。成功打包不等同实际匹配播放。

## 实现边界与检查

- 普通online与汽水imported共用MatchedResolver；自动开关仅影响普通在线，人工绑定始终优先。每个平台最多一个严格自动候选；先采用本次可靠搜索结果，再用该平台旧可靠记录补空，避免旧失效ID遮住新ID。搜索故障可继续已保存可靠目标；不确定版本不自动使用。
- 人工候选支持修改关键词、1–10页/每平台最多25条；两并发/每请求8秒预算、完整成功才缓存，所有平台失败保留旧列表。不是递归无限搜索。
- LibraryStore串行写入内比较原绑定引用及取消信号；手动变化使当前解析/已加载媒体失效，保留原条目与定位。自动记录发布不会取消自身。普通在线开关变化只清理正在解析或实际匹配媒体，不打断原曲或人工指定版本。
- 歌词和原生NowPlaying采用实际匹配目标；收藏、队列、备份保留原身份。仅有旧自动记录时，不把原曲成功播放误标成匹配播放。目标直接交给原LX路由，不递归读目标自己的绑定。
- 179项检查通过，覆盖质量顺序、解码排除键、版本约束/自绑定、备份、手动写竞态、开关与游标；合成App测试使用tests/e2e独立入口，仅注入provider HTTP，仍执行真实平台映射、LX原生宿主和PCM引擎。正式index不引用该入口，设备归档固定index并拒绝测试适配器标记。未证明真实用户歌曲、手机后台或签名。

补充竞态修正：人工取消自动匹配记录也必须废弃已加载媒体；此前只对manual记录变化监听会使自动记录清除后仍resume旧URL。已将明确删除记录纳入失效条件（自动成功发布仍不取消自身），新增游标保留回归，179项检查通过，并扩展App自动记录取消→重新自动匹配的验收。
