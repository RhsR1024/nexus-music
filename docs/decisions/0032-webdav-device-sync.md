## 同步范围与交互

- 本批同步收藏、本地歌单（条目 ID、顺序和重复项）、音频匹配和歌词选择。历史与聆听统计继续保留本机，避免多设备累加双计；凭据、音源、队列/播放意图、文件、设备媒体权限、外观资源也不上传。F33 总目标保留，自动触发/跨真实设备验收后续收尾。
- 每个已验证 WebDAV 账号可指定根目录内的同步目录；账号 ID 与规范化目录共同组成隔离空间。每设备持久化自己的 UUID 与各空间上次确认基线，不使用墙钟排序决定输赢。
- 先读取并展示合并预览，再明确确认。没有共同基线的首次连接视为合并两份独立数据，不自动用空本机清空云端。
- 同一收藏/歌单/匹配/歌词选择的基线、本机、云端作三方比较。一侧未变时采用另一侧；相同变化直接合并；双侧不同变化必须逐项选择本机/云端。同一歌单并发改名、改曲序或删除与编辑也必须选择，不以时间戳静默丢弃另一份。
- 删除保留有界 tombstone。初次连接遇到本机现有项与云端删除标记时必须确认冲突；离线设备基于旧基线重新上线不会复活已确认删除。超容量拒绝同步而非随意裁剪删除标记。
- 未建立压缩协议前，远端必须保留所有已确认记录及删除标记；发现丢失时拒绝提交并要求重新核对。收藏/歌单列表展示顺序保留各设备原有顺序，远端新增项按稳定身份追加；歌单内条目顺序按所选版本同步。

## 提交与错误恢复

- 使用独立格式 nexus-music-sync/v1，校验所有记录种类/ID/载荷及总量，清理每个 Track，未知版本或坏数据在写本机前拒绝。同步文件 32MiB 上限，凭据沿 Keychain，受限传输不变。
- GET 必须返回强 ETag。创建使用 If-None-Match:*，更新使用 If-Match；412 要求重新预览，不能自动用旧冲突选择重试。PUT 后用该 ETag 回读核对全部文档，服务端不支持强版本时拒绝同步。
- 确认在共享 MutationQueue 内复核本机同步范围是否仍与预览一致，再进行条件上传/回读；排队的本地修改在事务之后执行。历史/播放统计不参与同步替换。基线和音乐库用同一 SQLite 事务提交；预览期间本机数据变化须重新预览。
- 网络、取消、连接替换/删除及 CAS 失败不修改本机；远端接受但本地事务失败时明确提示重新预览核对，不承诺撤回服务器写入。提交中不提供假取消。连接切换废弃旧预览，不跨账户恢复。
- 目录逐层 stat/MKCOL 后复核目录，写拒绝重定向；GET 保留 If-Match，不回退无条件上传。原生 PUT 的扩展必须保留 F32 的创建保护及读取条件检查。

依据：RFC9110 §13.1.1 If-Match、§13.1.2 If-None-Match；RFC4918 §9.3 MKCOL。版本保证依赖服务端正确执行条件请求，不宣称端到端加密。

## 验证要求

纯三方合并、并发增删/改序/重复项、时钟回退无影响、断线/账号变化、畸形及越界数据、同一库/基线原子失败、预览后编辑、提交期间排队编辑、CAS竞争和不支持强 ETag；真实原生 HTTP 条件 PUT/GET/重定向回归，再实际 App 预览/冲突/重启及既有备份/播放回归。本地 SDK26.2 与云端 iOS27 分别记录；个人服务、两台实际设备和后台单独验收。
