# 多音源与音质路由决策

状态：实施中。用户明确要求参考Wayferar-Music多源启用/自动择源，不采用单一全局音源上下文。

## 对比与证据

固定提交见REFERENCE_COMPARISON.md。本次阅读Wayferar-Music SourceSelection.java的importLocal/controls/startOperation，Q1/F.smali的d/p/q/s，以及Java参考的对应方法。保留用户选择顺序、批量启停、失败保留选择、修改后清路由缓存；Q1/F按平台/音质/源版本记录失败与winner。不能直接复制Android Context、反编译Java或静态单例。

Q/wtf为LX完整请求模型及独立JSC契约参考；现有全局userApi链不能直接套成批量上下文。Cy隔离generation有价值，但其MusicSourceResolver只列flac/320k/128k，不能覆盖用户的更高档位。悦音主要提供探测器和provider，不能作为完整脚本宿主。采用原创TS路由策略+每脚本独立原生上下文；不直接搬入任何项目的状态管理或播放器依赖。

## 固定行为

- 已导入、用户勾选、实际已启用/初始化三种状态分开。批量启用尽可能完成各项，失败项保留待重试；更新同ID不新增重复源，保留顺序。
- 每脚本拥有自己的context/generation与请求表。停用/替换一个源只销毁它的上下文，不影响其他源。
- 外层按用户音质偏好向下，内层按已启用源顺序遍历。某源不声明当前档位直接跳过；失败/超时/无效URL继续下一个源。全部源当前档位失败后才降一级，不向更高档位尝试。
- 档位别名统一，实际调用仍传脚本声明的原始名称。特殊环绕/杜比等不凭名称保证比无损更高；候选链显式记录，不用UI八档当作真实文件质量证据。
- 返回保留sourceId/requestedQuality/resolvedQuality。resolvedQuality为“成功请求的档位”，实际编码/位深要由媒体后端探测，不把请求成功当作无损输出证据。
- 每个尝试有超时；取消必须中止本轮，不继续下一源/下一档。迟到结果不回写新请求，不含带认证的URL/原始错误日志。
- 音源启停/更新后立即影响候选快照，尚在途的旧源返回必须拒绝；不把一次曲目失败永久禁用整个源。
- 复用同一路由入口供播放、以后离线保存；元数据搜索provider独立于LX脚本。

## 验收

测试覆盖：高档失败跨源→降档、低偏好不升档、别名传参、禁用/替换取消、超时、无效URL、取消、重复源ID、批量部分失败和源顺序持久化。之后补24个实际脚本原生初始化/HTTP与真实曲目解析、PCM/播放/锁屏验收；只有全部对应关卡通过才完成M3。
