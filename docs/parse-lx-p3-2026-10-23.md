# LX能力声明预算与初始化边界 P3 回执

P3已按审计后的调用链接入：正式入口 `services.ts` → `SourceRegistry.restoreEnabled/setManyEnabled` → `createNativeLX.initialize` → `readLXInitialize` → `readLXCapabilities`；诊断入口复用同一 adapter。开关、初始化超时、revision 隔离仍由 Registry 管理，本次只收紧事件解析与预算，没有改变播放路由、音质标准化或平台登录行为。

预算数值是音枢本地策略，不是 LX 协议标准，也不代表 24 份本地脚本已在动态环境全部兼容。真实平台服务、登录态、真机和大脚本运行时仍未验收。

## 实施

|位置|行为|边界|
|---|---|---|
|`src/providers/lx.ts` `LX_INITIALIZE_MAX_BYTES`|初始化字符串在 `JSON.parse` 前检查 UTF-8 字节数，与原生 `ScriptRuntime` 1MiB 事件上限一致|手工按码点累计，不依赖 Node `Buffer`，可在 Hermes 运行；超限报“音源初始化响应超出上限”|
|`LX_NAME_MAX_LENGTH`|`name` 缺省或空串回退平台代码；显式非字符串或超256（UTF-16 单元）失败|不截断名称，不把坏类型静默当缺省|
|`LX_DECLARATION_MAX_ITEMS` / `LX_DECLARATION_MAX_LENGTH`|`actions`、`qualitys` 先按原始数组检查数量≤64、每项非空字符串≤128，再去重|先限后去重；重复洪泛不能靠去重绕过；原值不改写、不截断|
|五平台过滤|仅保留 `wy/tx/kw/kg/mg`，其余来源键忽略；合法动作只授予 `musicUrl/lyric/pic`|未知合法动作不授权；已在运行时由 `makeLXActionRequest` 再次拒绝|
|音质保留|未知 quality 按声明顺序去重后保留；`musicUrl` 请求必须命中已声明项；`lyric/pic` 允许空 `qualitys`|保留不等于协议已支持；未知音质不会自动参与标准化路由|
|整脚本失败|任一已识别平台的声明结构/预算/类型错误使该脚本整条失败；不发布部分能力|其他脚本由 Registry 隔离：失败源 `failed` 且按匹配 revision 销毁，其他源保持 `ready` 并可请求|
|诊断|`createNativeDiagnosticLX` 委托 `createNativeLX`，同样经过初始化字节预算|诊断不能绕过生产解析边界|
